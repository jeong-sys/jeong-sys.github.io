## 개요

코리아넷·코리아넷 CMS 의 운영·개발을 담당하며,
**요구사항 분석 → DB 설계 → 개발 → 테스트 → 운영 반영**의 전 주기를 단독 수행했습니다.
Java 1.7, Spring MVC + JSP, Tomcat 7, CUBRID 기반의 레거시 환경에서
**신규 서비스 구축**과 **기존 로직의 구조·성능 개선**을 병행했습니다.

`Java 1.7` `Spring MVC` `iBatis` `JSP` `jQuery/AJAX` `CUBRID` `Tomcat 7` `Maven` `SVN`

## 주요 기여

### 1. K-Info Hub 구축 — 조회 성능 94% 개선 및 운영 관리 체계 수립

**기간** 2026.04 ~ 2026.07 · **역할** 설계·개발 단독 수행

해외 이용자가 한국 관련 정보를 표제어(Headword) 단위로 탐색하는 신규 정보 허브를 구축했습니다.
서비스 화면 개발에 그치지 않고, **운영자가 표제어 콘텐츠를 지속 관리할 수 있는 CMS 체계까지 함께 설계**했습니다.

#### 1-1. 연관 콘텐츠(Related Contents) 계층 조회 로직 설계

- 상위/하위 표제어의 *연계 뉴스*와 *키워드 뉴스*를 4가지 조합으로 정의하고,
  하위 카테고리 기사가 상위 카테고리에서도 노출되도록 계층 구조를 정리
- 연관 콘텐츠가 없는 경우 표제어 키워드 기반 기사로 대체 노출하는 폴백(fallback) 처리
- 기사 없이 이미지만 등록된 케이스, 링크 미연결 상세 페이지 등 예외 시나리오를 사전 정의
- 중복 판별 로직을 JS가 아닌 **Java 서버 단으로 이관**해 클라이언트 부담과 데이터 정합성 리스크를 축소

#### 1-2. 쿼리 튜닝으로 응답 시간 4초 → 0.25초 (약 94% 단축)

- **문제**: `HEADWORD_CD = ? OR HEADWORD_CD IN (서브쿼리)` 구조에서
  서브쿼리가 전체 표제어를 조회한 뒤 외부에서 필터링 → 불필요한 풀스캔 발생
- **조치**: 자기 자신 조건(`HEADWORD_CD = ?`)과 그룹 조건(`HEADWORD_GROUP_CD = ?`)을
  **서브쿼리 내부 WHERE 절로 이동**시켜 조회 대상을 선제적으로 축소
- **결과**: 쿼리 응답 **4초대 → 0.25초대**, 네트워크 기준 **서버 응답 시간 53% 단축**

#### 1-3. 표제어 CMS 관리 게시판 신설 (실개발 5일)

현업·시스템관리자·유지보수 업체가 표제어 콘텐츠의 수정 요청 및 접수 현황을 관리하는 게시판을 신규 구축했습니다.

- 첨부파일 등록/삭제(확장자·개수 제한), 댓글·대댓글, 조회수, 엑셀 다운로드, 권한별 쓰기 제어
- **기존 테이블 재사용 대신 신규 테이블 생성**을 선택 — 향후 요구사항 변경 가능성을 고려했고,
  용도가 코드상에서 확인되지 않는 기존 컬럼(`cate_seq`)에는 임의로 값을 넣지 않는 원칙을 유지
- 댓글 테이블은 식별자만 분리해 기존 테이블을 공유하도록 설계, 중복 개발 방지
- 검색 조건이 페이지 이동 후에도 유지되도록 처리, 조회수 중복 증가(댓글 CRUD 시 2회 카운트) 예외 처리

#### 1-4. 기타 구현

- WiseNut 검색 솔루션 연동 및 JSON 응답 데이터 파싱·렌더링
- 조회수 집계를 AJAX 비동기 처리로 전환, 다국어별 통계 산출 및 엑셀 리포트 기능 구현
- 표제어 등록 시 대표 이미지·아이콘 등록, 이미지 유무에 따른 콘텐츠 영역 배경색 분기,
  다국어 번역(translation) 시에도 색상 정보가 유지되도록 저장 구조 개선

#### 트러블슈팅

> **운영 DB 부하 장애 원인 규명**
> 연산자 우선순위를 잘못 적용한 `AND (A OR B)` → `AND A OR B` 형태의 조건절로 인해
> 의도한 필터가 무력화되며 전체 테이블이 조회되어 DB에 과부하가 발생.
> 로그 분석으로 원인을 특정하고 조건절 그룹핑을 수정해 복구했습니다.

> **검색 후 뒤로가기 시 재검색 미동작**
> 브라우저 캐시가 이전 응답을 반환하는 것이 원인.
> `dispatcher-servlet`에 URL을 등록해 **Interceptor를 경유하도록 구조를 변경**,
> 항상 신규 요청으로 처리되게 하여 해결했습니다.

> **저장 후 요청 파라미터가 URL에 노출**
> Controller가 GET/POST 구분 없이 요청을 수신하는 레거시 구조가 원인.
> 컨트롤러 전면 수정 대신 **AJAX POST 호출 + 응답 메시지(userMsg) 기반 처리**로 전환해
> 영향 범위를 최소화하면서 성공/실패 알림까지 구현했습니다.

> **운영 환경에서만 조회수 미증가**
> 로컬·개발 서버에서는 정상 동작하나 운영에서만 실패하는 현상.
> 코드가 아닌 **환경 차이(테이블 정의, NOT NULL 제약)** 로 범위를 좁히는 방식으로 접근해 원인 특정.

### 2. SR게시판 만족도 조사 기능 설계 및 구축

**기간** 2026.02 ~ 2026.04 · **역할** 요구사항 분석·DB 설계·개발·테스트

요청 처리 품질을 측정할 수단이 없던 SR(Service Request) 게시판에
**만족도 평가 체계를 처음부터 설계해 도입**했습니다.

#### 설계 판단 — 확장 가능한 스키마 선택

3점 이하 응답 시 6개 유형의 불만족 사유를 다중 선택하도록 요구되었고,
저장 방식으로 세 가지 안을 비교했습니다.

| 방안 | 문제점 |
|---|---|
| 한 컬럼에 리스트로 저장 (`,` 구분) | 이후 통계 집계 시 문자열 파싱 필요 → 확장성 저하 |
| 사유별 컬럼 분리 | 사유 항목 변경 시마다 DDL 변경 필요 |
| **사유를 행 단위 + 코드값으로 저장 (채택)** | 통계 집계 용이, 항목 변경 시 코드 테이블만 수정 |

내용(문자열)이 아닌 **코드값**을 저장하도록 결정하여, 이후 사유 문구가 바뀌어도
과거 데이터 마이그레이션 없이 대응할 수 있는 구조를 확보했습니다.

#### 구현 범위

- 5점 척도 평가 UI 및 3점 이하 시 사유 선택 화면 (2-depth 코드 연동)
- 권한(A0101) 기반 만족도 점수 노출 분기 처리
- 엑셀 다운로드 — 동일 게시글의 복수 만족도 응답 시 셀 병합, 정렬 조건 및 검색 조건 유지
- JSP에 하드코딩되어 있던 만족도 코드를 **CMS 코드 관리 화면으로 이관**,
  운영자가 서버 재기동 없이 항목을 수정할 수 있도록 개선

### 3. 웹 로그 분석 데이터 수집 자동화 — 외부 도구 설치 불가 환경에서의 브라우저 네이티브 자동화

**역할** 기획·개발 단독 수행 (자발적 개선 과제, 총 2일 소요) · **환경 제약** 내부망, 외부 패키지 설치 불가

웹 로그 분석 솔루션(DataStory)에서 **10개 언어별 사이트의 IP 국가 방문자 통계**를
수집해 엑셀로 산출하는 작업을 자동화했습니다.
언어당 메뉴 클릭 → 날짜 선택 → 조회 → 수기 기록을 반복해야 했고,
반복 작업 특성상 오타·누락 위험이 상존했습니다.

**Selenium 등 자동화 도구를 설치할 수 없는 보안 환경**이었기에,
페이지에 이미 로드된 jQuery와 브라우저 콘솔만으로 구현했습니다.

#### 3-1. 동작 구조 — 자기 호출형 페이지 순회

```
URL 파라미터(profileId)로 현재 언어 식별
  → 메뉴 클릭 → 날짜 범위 설정 → 조회
  → 렌더링 대기 후 DOM에서 데이터 추출 (총 방문수 / 국가명·방문수 Top 5)
  → sessionStorage에 누적 저장
  → 마지막 언어? ─ No  → 다음 profileId로 페이지 이동 (반복)
                  └ Yes → .xls 파일 생성 및 다운로드
```

페이지 이동이 발생하면 JS 변수는 초기화되므로, **각 페이지 로드를 하나의 작업 단위로 삼아
자기 자신을 다른 파라미터로 재호출하는 재귀적 순회 구조**로 설계했습니다.

#### 3-2. 핵심 기술 요소

- **비동기 순서 보장** — 메뉴 클릭 → 날짜 설정 → 데이터 로딩의 실행 순서가 보장되어야 하므로
  각 단계를 Promise로 감싸고 `async/await`로 체이닝, 렌더링 대기는 `setTimeout`으로 처리
- **페이지 간 상태 유지** — 페이지 이동으로 소실되는 진행 상태(수집 완료 언어)와
  누적 데이터를 `sessionStorage`에 저장해 유지
- **외부 라이브러리 없는 엑셀 출력** — SheetJS 등을 쓸 수 없어,
  HTML 테이블에 엑셀 전용 XML 네임스페이스(`urn:schemas-microsoft-com:office:excel`)를 부여하고
  `Blob` + `URL.createObjectURL`로 `.xls` 다운로드를 트리거

#### 트러블슈팅

> **URL 길이 초과로 순회 중단 (414 추정)**
> 누적 데이터를 URL 파라미터로 다음 페이지에 넘기는 구조여서, 언어를 순회할수록 URL이 길어져 요청이 실패.
> **데이터 전달 매체를 URL에서 `sessionStorage`로 변경**해 URL 길이와 무관한 구조로 전환했습니다.

> **엑셀에 마지막 언어 데이터만 출력**
> 페이지 로드 시 초기화 조건이 URL 파라미터 기준이라, `sessionStorage`에 누적된 데이터를 무시하고
> 매 순회마다 새로 초기화되던 것이 원인. **초기화 조건을 `sessionStorage` 존재 여부로 변경**해 해결.

> **비율 값이 `28.00%`로 변형되어 표시**
> 엑셀이 `28.0%` 문자열을 퍼센트 서식으로 자동 인식하는 것이 원인.
> 셀에 `mso-number-format:'\@'`를 지정해 텍스트로 강제하여 원본 값을 보존했습니다.

#### 성과

- 10개 언어 × 다단계 클릭·대기·기록의 수동 작업을 **콘솔 명령 1회 실행으로 대체**
- **정기 통계 보고서 완료 시점을 오후 3~4시에서 오전 중으로 앞당김** —
  하루 중 오후 시간대 전체를 다른 개발 업무에 배분할 수 있게 됨
- 외부 프로그램 설치 없이 브라우저 기본 기능만으로 구현하여,
  **동일한 보안 제약을 가진 다른 내부 시스템에도 이식 가능한 방식**을 확보
- 별도 지시 없이 반복 업무의 병목을 직접 식별해 **2일 만에 도구화**

### 4. AEO(AI 답변 최적화) 가이드 적용 — 공공기관 영문 사이트 진단 조치

**기간** 2026.06

생성형 AI 검색이 공공 정보를 인용하는 흐름에 대응해, 영문 서비스에 AEO 가이드를 적용했습니다.
단순 SEO 개선이 아니라 **AI가 페이지를 사실 정보로 인용할 수 있는 구조**를 만드는 작업이었습니다.

- `<title>`·`<description>` 문구 및 메타태그 전면 재정비, 불필요 공백 제거
- **FAQ 구조화 데이터를 스크립트뿐 아니라 HTML 본문에도 함께 노출** —
  스키마 마크업만으로는 AI 파싱이 보장되지 않는다는 점을 진단 과정에서 확인하고 반영
- 사이트의 설립 목적·역할 등 **핵심 사실 정보가 페이지 내에 명시되어 있지 않음**을 발견,
  콘텐츠 추가를 제안
