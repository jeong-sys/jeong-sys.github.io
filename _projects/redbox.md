## 개요

"우리의 봄" 팀에서 진행한 프로젝트입니다. 헌혈증을 양도받으려면 헌혈자가 직접 증서를 양도해야 해서 접근성이 제한된다는 문제를 해결하기 위해, 웹으로 헌혈증을 등록하고 필요한 사람에게 기부하거나 요청할 수 있는 시스템을 개발했습니다. 사용자 요청 게시판과 관리자 승인 게시판을 담당했습니다.

## 기술 스택

`Spring Boot` `MariaDB` `React` `K6` `Redis` `EC2` `S3` `RDS`

## 주요 기여

### 1. 사용자 요청 게시판 설계

요청 게시글의 등록·조회·수정·삭제 CRUD와 S3 첨부파일 업로드·수정·삭제 기능을 구현했습니다.

- 요청 게시글 조회 시 정렬 기준(최신순, 만료순, 좋아요순)을 어떤 방식으로 전달할지 고민하다, API 엔드포인트를 분리하는 대신 파라미터로 정렬 기준을 구분하는 방식을 채택했습니다.
- 게시글 좋아요 데이터 변경 시 Delete 후 Insert할지 Update할지 검토한 끝에, 정합성을 위해 Update 방식으로 처리했습니다.
- 동일한 response를 사용하는 상세 조회에서 조회수가 중복으로 증가하는 문제를 발견해, 조회수 증가 로직을 별도로 분리해 방지했습니다.

### 2. 관리자 승인 게시판 및 부가 기능

사용자 요청 게시글에 대한 승인·거절 권한을 관리자에게 부여하는 승인 게시판을 구현했습니다. 외부 API를 연동해 헌혈의 집 조회 기능을 추가하고, 스케줄러를 활용해 데이터를 주기적으로 업데이트하도록 구현했습니다. 이 외에 회원 탈퇴 기능도 함께 개발했습니다.

### 3. 성능 개선 — Redis 캐싱 적용

K6 부하 테스트로 Redis 캐싱 적용 전후 성능을 비교해 캐싱 효과를 수치로 검증했습니다. RESTful 원칙에 따라 API·엔드포인트를 설계하고, JPA 구조로 도메인을 모델링하며 효율적인 데이터 매핑 방법을 익혔습니다.
